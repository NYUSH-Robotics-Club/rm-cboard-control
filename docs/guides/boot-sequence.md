# 启动顺序与 LED

`Src/main.c` 完成初始化后调用 `RobotRtos_Start()`；静态控制任务执行
`AppRuntime_Step()` 和控制循环。LED 只能定位大致阶段，不能替代日志和反馈。

| 顺序 | 颜色 | 阶段 | 可能等待 |
|---:|---|---|---|
| 1 | 红 | CubeMX 外设完成，初始化蜂鸣器、IMU、消息中心、遥控、日志 | 由 IMU 初始化实现决定 |
| 2 | 黄 | CAN、电机、云台初始化 | 无固定 CAN 延时 |
| 3 | 青 | 等两轴反馈，yaw锁存实际角，pitch采用配置初始目标 | 最长 5 秒 |
| 4 | 蓝 | IMU 校准，仅配置启用时出现 | 由校准实现决定 |
| 5 | 品红 | Cmd、底盘、发射订阅初始化 | 无 |
| 6 | 品红 | 哨兵舵轮对齐，仅 sentry | 最长 5 秒 |
| 7 | 白 | 视觉、ESC 等待、WT61C DMA | ESC 200 ms |
| 8 | 绿 | 启动 FreeRTOS；运行后由离线报警接管灯色 | 随反馈状态变化 |

## 关键顺序

1. HAL、时钟、GPIO、DMA、CAN、SPI、I2C、UART、USB、TIM 初始化。
2. 初始化消息中心、遥控和 Logger，然后启动 CAN manager。当前入口未处理
   CAN manager 的返回状态，排障时须检查总线反馈与后续安全锁定状态。
3. `MotorDriver_ModuleInit()` 装载当前车型的 DJI 兼容状态；
   电机服务在首次使用时初始化厂商 adapter。
4. `GimbalApp_Init()` 后调用 `Gimbal_WaitForAlignment()`。控制器只有在两轴反馈
   有效后才开始对齐：yaw 锁存当前位置，步兵 pitch 追配置的 1971 编码目标。
5. 若车型启用 IMU 校准，校准期间每约 5 ms 发布零速保持命令；反馈未就绪时
   云台仍输出零；步兵 pitch 在反馈有效后追配置的 1971 编码目标。
6. 初始化 Cmd、底盘、发射、遥控日志订阅、视觉和 WT61C。
7. 初始化可选应用，然后创建静态控制任务并启动 FreeRTOS 调度器。

## 初始化后的周期

控制任务进行 IMU 更新、可选应用步进、命令处理、消息派发、电机离线报警
与限流 CAN 统计，最后调用 `vTaskDelay(2)`。1 kHz tick 下，这保留旧
`HAL_Delay(1)` 在完成一轮工作后等待两次 tick 的语义，不追赶错过的周期，
避免按回调次数累加的 pitch 目标和发射斜坡加速。电机服务在派发后的 hook
中刷新；实际周期、抖动和栈余量仍需实测。

## 云台仍突跳时检查

1. yaw/pitch 的 CAN RX ID 与通道是否正确，首帧是否都在 5 秒内到达；
2. yaw 目标是否锁存首帧角度、pitch 目标是否为配置的启动值；
3. `direction`、pitch 重力补偿符号和编码器环绕是否正确；
4. 是否有其他模块在上电锁存完成前发送非零电流；
5. PID 是否在捕获位置后清零。

当前源码已接回 RTOS；板上运行和运动安全仍需验证。
