# CAN1 四轮配置与检查（2026-09-13）

用户要求四轮接 CAN1，逆时针编号 1、2、3、4。当前按步兵 M3508/C620
配置处理，暂定俯视左前为 1 号，车头为前；起点和实物型号尚待用户确认。

| 轮号 | 暂定位置 | 电调反馈 ID | 命令 ID | 命令槽（从 0 起） | 源码逻辑 ID |
|---|---|---|---|---|---|
| 1 | 左前 | 0x201 | 0x200 | 0 | 0 |
| 2 | 左后 | 0x202 | 0x200 | 1 | 2 |
| 3 | 右后 | 0x203 | 0x200 | 2 | 3 |
| 4 | 右前 | 0x204 | 0x200 | 3 | 1 |

配置文件为 `config/robots/infantry_standard.c`。数组保持运动学使用的左前、
右前、左后、右后顺序，只调整反馈 ID 和命令槽。方向和 PID 未经本次实车验证。
这是控制板的映射配置，不会改变电调内部硬件编号；实际轮位对应关系仍需逐轮核对。

## 实机只读结果

ST-Link 检测到 STM32F407 系列 ID `0x101f6413`，电压约 3.33 V，CPU running，
CFSR/HFSR 为 0。使用 OpenOCD 关闭 examine-end 事件，仅执行运行中内存读取。
本次没有暂停、复位、烧录或发送测试运动命令。

板上 Flash 前 146256 字节与
`build/linux-aarch64-306202d6/inf-debug/NYUSH_Infantry.bin` 完全一致，SHA-256：
`8e5a1434bcc1a51cb120ca5193b4ca42cf857abf28a0b35d2037c958817a75e6`。
采样地址按该 ELF 的调试符号确定，不能使用当前源码结构解释板上内存。

40 组采样跨 4210 ms，每轮反馈时间戳有 40 个不同值：

| 反馈 ID | 板上逻辑 ID | 转速范围（电机 RPM） | 编码器范围（刻度） | 结论 |
|---|---|---|---|---|
| 0x201 | 1 | 0 | 29 | 在线，未验证转动 |
| 0x202 | 2 | 0 | 3015 | 在线，未验证转动 |
| 0x203 | 3 | −3～2 | 3904～3906 | 在线，微动不足以证明能转 |
| 0x204 | 4 | 0 | 1780 | 在线，未验证转动 |

CAN1 总接收计数增加 21159，发送错误计数保持 0，ESR 所有采样为 0。
总接收量包含其他电机，不能作为每轮帧率。字段为非原子读取；先读 tick 再读反馈，
因此时间差会出现几毫秒负数。原始记录保存在被忽略的
`build/diagnostics/chassis-20260913/`，包含 Flash、读取脚本、日志和 summary.json。
