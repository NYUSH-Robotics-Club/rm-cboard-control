# CAN 故障恢复与重新使能

`BspCan_Service()` 在控制任务调用链处理 CAN1/CAN2 的 Bus-Off 恢复。
故障时两路电机输出均锁定，
先取消硬件邮箱旧报文并清 DJI 软件发送缓冲，再等待总线退出故障。
超时保持停机并延迟重试；恢复不会修好供电、接线或终端电阻。

## 解锁条件

两路 CAN 健康后，仍需遥控在线、两只拨杆下位、模拟通道回中并稳定
满足控制器的确认窗口，才解除输出锁定。解锁当次不会重发故障前
的非零指令。云台还须等待新鲜反馈并重新对齐；发射机构重连后
沿用其拨杆重新使能规则。详细条件以 `bsp/can/bsp_can.c` 和
`application/cmd/cmd_controller.c` 为准。

正常下档时摩擦轮按速度斜坡减到零并保持速度闭环；CAN 锁定或
反馈失效时则清目标/PID并给零命令，两种停机行为不能混同。
零命令是软件请求，断线电机不一定收到，机械也不会瞬间停稳。

## 诊断边界

CAN1/CAN2 均开启硬件自动重传，仲裁失败后继续等待发送机会。
该设置作用于两条总线的全部发送邮箱，包括云台、底盘和发射电机。
重新用 CubeMX 生成 `Src/can.c` 时须核对该设置。

两条总线均限制同一标准ID最多占用一个在途邮箱。DJI软件聚合器在邮箱忙或提交
失败时保留一份最新待发值；后续命令按电机槽位覆盖，不追加历史队列。接收进入
邮箱后才清除软件待发标志。`tx_ok`计邮箱接受，`tx_busy`计延后，`tx_err`计提交
错误；邮箱接受不等于总线发送成功，两路硬件均会自动重传。

普通更新不取消正在重传的帧。完整8字节全零帧是停机例外：若同ID旧非零帧仍在途，
先请求取消一次，等待邮箱释放后再提交最新值；不直接改写正在发送的邮箱。
组合帧中单个电机归零、其他电机仍非零时仍遵循普通最新值等待规则。
Bus-Off沿用两路邮箱取消和输出锁定；刷新入口及途中发现失能后均清零软件保留值。
正常发送仍取决于总线是否可用，不保证零指令能在断线时送达。
自动重传后，仲裁丢失不一定作为一次最终发送失败出现；判断改善应比较发送
完成间隔和反馈电流响应，不能只看 ALST 事件数量下降。

`BspCan_GetRecovery()` 可读取两路恢复阶段与故障计数；
`MsgCenter_GetDiagnostics()` 提供队列覆盖和派发上限计数。
发送提交次数不等于电调已经执行。主机测试模拟状态机与回中解锁，
不能证明真实总线电气问题已消除。每次实车诊断应保存对应的固件
身份、采样时间、CAN 状态和电机反馈；历史窗口不能代表现在。
