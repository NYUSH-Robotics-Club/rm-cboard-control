# CAN 故障恢复与重新使能

`BspCan_Service()` 在控制任务调用链处理 CAN1/CAN2 的 Bus-Off 恢复。
故障时两路电机输出均锁定，
先取消硬件邮箱旧报文并清 DJI 软件发送缓冲，再等待总线退出故障。
超时保持停机并延迟重试；恢复不会修好供电、接线或终端电阻。

## 解锁条件

两路 CAN 健康后，仍需遥控在线、两只拨杆下位、模拟通道回中并稳定
满足控制器的确认窗口，才解除输出锁定。解锁当次不会重发故障前
的非零指令。云台还须等待新鲜反馈并重新对齐；发射机构重连后
沿用其拨杆重新使能规则。详细条件以 `bsp/can/bsp_can.c` 和
`application/cmd/cmd_controller.c` 为准。

正常下档时摩擦轮按速度斜坡减到零并保持速度闭环；CAN 锁定或
反馈失效时则清目标/PID并给零命令，两种停机行为不能混同。
零命令是软件请求，断线电机不一定收到，机械也不会瞬间停稳。

## 诊断边界

CAN1/CAN2 均开启硬件自动重传，仲裁失败后继续等待发送机会。
该设置作用于两条总线的全部发送邮箱，包括云台、底盘和发射电机。
重新用 CubeMX 生成 `Src/can.c` 时须核对该设置。

两条总线均限制同一标准ID最多占用一个在途邮箱。DJI软件聚合器在邮箱忙或提交
失败时保留一份最新待发值；后续命令按电机槽位覆盖，不追加历史队列。成功进入
邮箱后才清除软件待发标志，槽位当前值和时间仍保留以检测输出停止更新。`tx_ok`计邮箱接受，`tx_busy`计延后，`tx_err`计提交
错误；邮箱接受不等于总线发送成功，两路硬件均会自动重传。

普通更新不取消仍在有效期内重传的帧。完整8字节全零帧是停机例外：若同ID旧非零帧仍在途，
先请求取消一次，等待邮箱释放后再提交最新值；不直接改写正在发送的邮箱。
组合帧中单个电机归零、其他电机仍非零时仍遵循普通最新值等待规则。
Bus-Off沿用两路邮箱取消和输出锁定；刷新入口及途中发现失能后均清零软件保留值。
正常发送仍取决于总线是否可用，不保证零指令能在断线时送达。
自动重传后，仲裁丢失不一定作为一次最终发送失败出现；判断改善应比较发送
完成间隔和反馈电流响应，不能只看 ALST 事件数量下降。

`BspCan_GetRecovery()` 可读取两路恢复阶段与故障计数；
`MsgCenter_GetDiagnostics()` 提供队列覆盖和派发上限计数。
发送提交次数不等于电调已经执行。主机测试模拟状态机与回中解锁，
不能证明真实总线电气问题已消除。每次实车诊断应保存对应的固件
身份、采样时间、CAN 状态和电机反馈；历史窗口不能代表现在。

## 命令有效期

两车型每个DJI电机显式配置`tx_command_ttl_ms=20`、`tx_abort_timeout_ms=20`，
分别表示从输出生成到允许发送的寿命、取消请求到邮箱释放的等待上限；配置0采用20ms兼容默认值。
值是初始工程配置，不是硬件保证的发送截止时间。每个槽位独立记录HAL/BSP生成时间，
忙重试、组帧、其他槽位更新均不续期。提交后仍保留槽位年龄，停止更新也会产生零命令。
软件槽位过期时清零该槽位并重新组帧；非零帧采用各非零槽位中最早的截止时间。
未过期的其他槽位可继续使用当前值。全零停机状态不因年龄被丢弃或反复取消。

BSP按每通道三个邮箱检查在途截止时间，过期仅请求一次取消；确认邮箱释放后才允许
同ID最新帧进入。取消失败或等待到期进入既有双路输出锁定/CAN恢复流程，需要原遥控确认解锁。
发送与取消可能竞争；观察到TXOK单独计数。`abort_completed`仅表示取消后邮箱已释放且
未观察到TXOK，不表示电调确认或证明此前完全没有发送。已发出的旧帧不能撤回。

检查和聚合均在原control任务执行，无新任务、堆分配、阻塞重试或延时。
`CmdController_Task`调用服务前重新取HAL/BSP时间，不用可能早于本轮发送的循环入口时间。
截止检测误差仍包含任务调度/执行间隔及硬件取消时间；任务若卡住，软件不能按期取消。
PID、目标来源、遥控超时、pitch限位均不由本机制修改。RTOS运行时抖动和20ms配置需上板验证。

设计参考：[OpenCyphal bxCAN过期邮箱取消](https://github.com/OpenCyphal-Garage/platform_specific_components/blob/master/stm32/libcanard/bxcan/src/bxcan.c)、
[libuavcan发送截止时间接口](https://github.com/dronecan/libuavcan/blob/main/libuavcan/include/uavcan/driver/can.hpp)。
仅采用截止时间设计，不引入其协议或动态队列。
