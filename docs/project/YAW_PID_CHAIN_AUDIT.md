## 特定方向与过零检查

用户补充振动经常发生在特定方向，要求排查GM6020过零。重析上述P200同镜像日志，
以绝对RPM>25筛出的26个异常速度样本位于原始编码5055～6106；16个PID饱和样本在5137～6029。
筛选阈值仅供定位，不等于振动检测器。异常区距离编码8191/0边界很远，不支持本次异常由
机械角度回绕直接触发。之前7408→324的两个样本相隔0.803秒，边界瞬间落在采样空窗，

## 首轮源码配置与实际链路

| 项目 | 磁盘值 / 行为 |
|---|---|
| 速度调试 | `speed_loop_only=true`，位置外环旁路 |
| 手动目标 | `clamp(-deadband(ch0)/660 * 100/6, ±30)` RPM，满杆约16.667 RPM |
| 速度 PID | 振动时用户确认Kp=300；检查结束前磁盘Kp=120。Ki=Kd=0、输出限30000、积分限0 |
| 位置 PID | 10/0/0、输出限120000；当前不参与计算 |
| 输出滤波 | `output_lpf_rc=0.002` 秒，I/D清零不关闭滤波 |
| 前馈 | 全0关闭 |
| 发包 | CAN1、软件ID5、TX2FE槽0、电流原始刻度、最终限12000 |
| 反馈 | RX209，字节0/1为编码、2/3为有符号整数RPM、4/5为有符号电流 |

路径：`command_router.c::route_gimbal` → 云台命令最新槽 →
`gimbal_controller.c::GimbalController_YawControlWithCompensation` →
`PID_Calculate(inner, speed_target, speed_feedback)` → 应用协议限幅并转int16 →
`MotorService_CommandCurrent` → DJI适配器限幅 → `MotorDriver_SendCurrent` →
CAN管理器按槽缓存 → 消息派发结束hook集中发送 → 电调内部电流环。

接收按总线和RX ID找到配置，CAN管理器将反馈放最新状态槽，电机驱动回调更新同一ID5上下文。
消息中心先派发反馈状态，再派发控制，最后发送。应用电流路径不调用驱动旧位置/速度PID，
也不再乘direction；当前yaw方向为+1。软件误差为目标RPM减反馈RPM，未见单位混用、
符号额外翻转、重复软件闭环或角度跨零直接改变速度目标。实物出力方向仍须运动记录核对。

普通回中目标0 RPM，不锁角。speed-only下spin/vision也强制0 RPM；位置目标和领先角仅作备忘。
P300窗口用户最初不确定开关，随后称应该为true；后续P200只读复测已确认true。
连续反馈/控制间隔大于20 ms会作废yaw跟踪，双轴归零，重新等待100 ms稳定反馈；
另有遥控、CAN和pitch启动范围联锁。若运行中反复失效/恢复，也可能表现为断续出力。

## 检查发现

### 1. PID内部与实际输出限幅不一致，并影响输出历史

PID最后把内部输出存入`last_output`，云台随后才按12000裁剪发送。因此内部滤波历史
可以达到30000，超过实际发送值。反向误差出现时，旧输出仍参与计算，延迟制动。
I=0也存在这一现象；不能称为当前积分饱和。

按用户确认的振动参数P300、4 ms举例，初始化且I/D历史为0时，现有算法为：

```text
P[k] = 300 * (目标RPM - 反馈RPM)
u[k] = clamp((2/3)*P[k] + (1/3)*u[k-1], ±30000)
发送[k] = trunc(clamp(u[k], ±12000))
```

使用真实`pid.c`和本轮最初保存的P300车型参数，先以构造反馈建立内部30000，再将目标设0、反馈设+1 RPM：
P立即为-300，但五次输出依次约9800、3066.67、822.22、74.07、-175.31。
前四次仍沿正方向出力。该输入阶跃用于暴露算法状态，**不是机械模型或实车波形**。
建议先统一有效限幅，保证输出滤波历史与允许发送值一致；不能据此保证消除所有振动。
将来启用I或前馈时，还需让抗饱和逻辑感知最终执行限幅。

### 2. P=300直接放大整数RPM反馈波动

反馈每变化1 RPM，滤波前P变化300原始刻度。目标为0、构造反馈每4 ms交替+1/-1 RPM时，
真实PID滤波后输出收敛为约-150/+150，I/D始终0；若保持反馈0，重置后输出恒0。
因此算法没有凭空制造振动，但会响应反馈波动。反馈量化、真实低速反转、静摩擦、
机构弹性及增益/延迟可能共同形成振动，尚未分离。

### 3. 控制周期不是注释所称的固定1 kHz

冻结main依次更新IMU、路由、派发/控制/发送和报警，再延时1 ms。
`BspTime_NowUs()`实际为`HAL_GetTick()*1000`，只有毫秒分辨率。
PID按时间差换算秒，但同毫秒重复调用会回退到1 ms；输出滤波权重仍随dt变化。
历史实测内环多为3～5 ms，本次没有测量当前周期，不能沿用为当前实测值。

### 4. 恢复位置环前仍需重新配置

当前outer P10以编码刻度为误差，1°约22.756刻度，对应未限幅约227.56 RPM，
随后被手动30 RPM裁剪；约0.132°误差就达到该模式速度上限（稳态、滤波收敛时）。
不能只关闭speed-only就期待平稳锁位。外环还以`actual=-angle_error`实现误差输入，
其测量微分实际上也响应目标变化；当前外环旁路、D=0，不是本次速度单环振动来源。

## 纯P为什么仍会振动

理想连续、无延迟、刚性的一阶速度对象，负反馈P通常表现为阻尼；这个直觉有适用前提。
真实采样控制使用过去的测量，输出还经过滤波和电调，增益过大时制动力可能来迟并反复过冲。
位置P更不能保证无振动：到目标时力矩可以为0，但速度和惯性不会因此瞬间消失。
[NI控制理论说明](https://www.ni.com/en/shop/labview/pid-theory-explained.html)也明确比例增益过高可导致振荡。
下游限幅需要参与控制器状态管理，可参考
[MathWorks抗饱和说明](https://www.mathworks.com/help/simulink/slref/anti-windup-control-using-a-pid-controller.html)；
本次滤波历史现象的证据来自本库数值实验，而非将积分理论套用于I=0。
