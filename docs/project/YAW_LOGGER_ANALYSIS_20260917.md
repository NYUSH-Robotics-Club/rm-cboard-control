## 为什么角度目标看起来滞留

69.279～71.061秒，`gimbal_cmd_yaw_deg`始终778.08105度，实际角度由748.08105度
微移至747.94922度；与此同时速度目标和速度反馈82帧全0。
`gimbal_yaw_target_deg`为NaN，yaw_flags=15不含位置环有效位。

结合当前源码：`YawReference_Advance`按杆量积分角度参考，受领先量限制，杆量为0时直接返回，
所以角度参考停在最后值。速度单环通过杆量直接产生RPM目标，角度误差不进入速度PID。
本段约30度残差符合参考角领先限制及停止推进的行为，不是速度环仍在追778度。
若用户所指是画面的角度目标没有回到实际角度，本段可以解释；若指反打后速度目标方向不变，
这份TXT不能证明是否触发此前的跳变过滤问题。不能由角度参考平台倒推摇杆值。

## 能定位到哪里，尚不能定位到哪里

日志支持：下游确实采用了正/负/零目标，但闭环在部分窗口出现大幅速度反馈摆动和持续跟踪误差。
目标归零后仍有大幅反馈，不能仅用“旧非零目标滞留”解释；恒定非零目标也不能证明它符合当时杆量。
数据尚不能区分PID增益/输出动态、控制时序、机械负载及反馈异常，也不能证明电流已经交替饱和。

TXT缺原始ch0、路由yaw_rate、最终电流请求、PID项及控制dt；当前二进制Dashboard有原始杆量字段，
但这些TXT没有保存。下一次应同步保存这些量和固件/PID身份，才能区分输入滞留与目标正确后的闭环问题。
