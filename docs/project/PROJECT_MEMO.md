# 项目状态与约束

本页只记录跨任务仍有效的约束和未决问题，不保存逐次调参日志。以下“当前”
指仓库源码；板上固件及运动表现必须用匹配的 ELF、烧录记录和实车数据另行确认。

## 不变的边界

- 目标板为 STM32F407 C 板；当前车型仅 `infantry_standard` 与 `sentry_swerve`。
- `Src/main.c` 完成上电初始化后调用 `RobotRtos_Start()`；单个静态
  `control` 任务承接控制循环，空闲任务也使用静态内存。每轮末尾等待两次
  1 ms tick，保留旧 HAL_Delay(1) 的节奏；板上运行仍待验证。
- 底层基线冻结范围见根目录 `AGENTS.md`。过去的一次性授权不适用于后续改动。
- 依赖方向是 `application -> core/services/adapters -> modules -> bsp -> HAL`。
  业务不直接拼 CAN 帧，跨应用数据通过 `core/contracts/` 和消息中心传递。
- 不猜未知硬件参数。DM、本末、瓴控适配器已有源码，但现有车型只配置 DJI；
  Jetson 视觉口仍返回不支持。新电机/视觉协议须拿到型号和协议后再接实车。
- 任何构建和主机测试只能证明对应源码与测试条件，不能证明已烧录或实车安全。

## 源码中的步兵配置

以下数值来自 `config/robots/infantry_standard.c`；变更时应以该文件为准：

- 四全向轮，软件/电调 ID 按左前、右前、右后、左后为 **2/1/4/3**；
  X 形 45°、轴距与轮距 0.54 m、半径 0.07 m、P19 减速比 3591/187。
  轮子安装方向与带载控制仍须在相应实车上验证。
- 云台朝车头的编码参考为 4890，`yaw_ccw_sign=-1`。配置注释中的方向
  待实车确认；不能由软件符号推定物理方向。
- yaw 为 CAN1 硬件 ID5、RX 0x209、TX 0x2FE 电流指令；
  `speed_loop_only=false`，即源码选择位置与速度串级闭环。
  pitch 为 CAN2 硬件 ID4、RX 0x208、TX 0x1FF 电压指令。
- pitch 目标编码范围为 1607～2374，启动目标与重力零点均为 1971。
  这些是软件配置，不证明机械端点或越界保护已经实车验证。
- 小陀螺的 `SPIN_WZ_NORM=10` 会被全向轮策略裁到 1；
  `max_rotation_radps=1.20` 才是配置的角速度上限。云台跟随、
  车体自转和世界坐标平移是不同的量，参见路由实现。

## 当前需要解决

- 改动控制配置时同步核对注释中的方向、单位和限位；现有方向说明仍需实车确认。
- pitch 机械安全端点、输出方向、边界反复启停风险，以及 yaw/小陀螺
  的带载行为均需匹配固件的实车数据判定。历史日志结论不自动适用于当前板上镜像。
- RTOS 时序、栈、共享状态、Jetson 协议和非 DJI 电机接入尚未验证。
  不应把已编译的预留代码描述为可直接使用的整车功能。

## 验证入口

先用 `CC=gcc sh tests/host/run_tests.sh` 做主机回归；固件分别执行
`just build infantry_standard` 与 `just build sentry_swerve`。
`just flash-plan` 只生成计划，`just flash` 会写入目标板。具体行为见
[构建与烧录](../quickstart.md)。只在对应变更影响本页事实时更新本页，
不要追加任务流水账。
