# 按证据定位

## 验证层级

| 观察 | 能证明什么 | 下一步 |
| --- | --- | --- |
| USB 枚举/串口能打开 | 电脑可访问一个转接设备 | 匹配后端，确认电机供电，再读参数 |
| OpenOCD examination succeed、目标电压 | SWD 可访问 MCU | 确认固件/ELF 与 RTT 控制块 |
| RTT hello/status 成功 | RTT 双向通道与命令解析有效 | 检查 CAN 通道状态 |
| 内部静默回环出现 TX_OK/RX | CAN 控制器内部收发与回调路径可用 | 检查外部收发器、供电和线路 |
| TX_QUEUED | 邮箱接受了帧 | 等 TX_OK/TX_ERROR/TX_TIMEOUT |
| 正常模式 TX_OK | 总线上至少有节点 ACK | 核对目标电机实际回复与参数关联 |
| 匹配 ID/RID 的新参数回复 | 目标协议双向收发可用 | 再读模式/范围或执行已授权动作 |
| 新反馈状态 1 且角度持续变化 | 电机已使能并有运动反馈 | 用角度差/时间差核对速度 |
| 新反馈状态 0 | 收到失能状态 | 若要求机械完全停转，还需位置/速度变化或观察 |

## 常见问题与处理

**电脑检测不到设备**

- 查数据线、USB 口、设备型号和占用进程，不先改 CAN 协议或电机 ID。
- Mac `system_profiler`/libusb 空列表不是绝对的断线结论；本环境曾元数据为空而
  OpenOCD 实际能打开 ST-Link。用实际探针打开结果补充验证，区分元数据与连接证据。
- `open failed` 说明当前 OpenOCD 没能打开探针，不能据此判断 CAN 接线。
- 多个探针/串口不要猜选；没有设备或多个候选时保留不确定性，必要时让用户确认物理目标。

**USB2CANFD SDK 返回 0 台**

- 核对固件是否为 HDSC CDC（实际样本 2e88:4603）。有串口则走匹配的串口库。
- 若没有对应标识，不套用这个特例；核对官方后端和设备版本。

**SWD 好、CAN 全失败**

- 先核对 C 板完整供电，再看电机独立供电、CAN 口与调试串口区别、H/L/公共地、
  终端及当前波特率。ST-Link 给 MCU 供电不能替代板上 CAN 收发器的电源。
- 在已确认内部静默回环模式后可发一个内部测试帧；确认正常模式再读目标电机参数。
  不在外部未知节点上乱发用来测试回环的控制帧。
- 对 J3507 采用已实测的八字节参数读取，与官方 SDK 一致；不要因 TX_QUEUED 就声称收到回复。

**CAN 错误码/计数**

- 查看 ESR 的 TEC/REC/LEC、Bus-off/Error passive、last_tx_tsr、rx_callbacks/rx_frames。
- STM32 bxCAN LEC=3 是 ACK 错误；LEC=5 是 bit-dominant 错误。它们是定位线索，
  不是某个断线/接反/供电问题的唯一诊断。LEC 是最近错误，计数可保留此前历史。
- 根因排除后用新的一组请求比较增量。不要盲目重发运动帧、改所有 ID、自动恢复后宣称正常。
- 若 TX_TIMEOUT 后仍 BUSY，取消尚未确认，不能把邮箱当空闲；保留这个状态并检查硬件。

**TCP 端口还在、RTT 不回复**

- TCP 能连或 OpenOCD 进程仍在，不代表 MCU 正在运行或 RTT 解析器仍响应。
- 新的 hello/status 超时就保留通道失效结论；不能继续凭缓存声称电机在线或已停。
- 运动过程中遇到此情况，独立尝试零速/失能；仍未确认则告知操作者现场断电，
  不自动重启控制循环或使能。只读核对目标连接状态，未经授权不靠复位/重刷来掩盖原因。

**RTT 有回复、CAN 无 RX**

- 确认所选 CAN1/CAN2 与实际插口一致，正常模式不是只听/回环。
- 已知 J3507 为查询应答，空监听不保证会主动上报。
- 比较电机实际 ID、反馈 ID、模式、CAN/CAN FD 设置。F407 只支持经典 CAN，不能接收 FD。
- raw RX ID=0 是本次电机有效的反馈 ID，不应过滤为非法或“没有 ID”。

**读到全零/状态 0**

- 先问“有没有新帧”，检查 raw 字节、接收计数或覆盖 recv_data 的计数/时间戳。
- 参数缓存清对应 RID 后再读。状态刷新超时则保留未确认结果。
- 主机解码 P/V/T 必须来自本台电机当前参数；它们是映射范围，不是机械安全限值。

**发出停止后没有回复**

- 停掉持续写速度的进程；避免两个客户端对同一电机相互覆盖命令。
- Ctrl-C/SIGINT 走退出处理。零速失败也独立尝试失能，随后请求一条新状态。
- 仅有 TX_OK 仍不能宣称已停止；没有新回复时说明“停止指令已发送/停止未确认”。
  链路断开后不存在软件保证；按现场条件由操作者断电处理。

## 记录最小证据

保留所用链路、固件/ELF 匹配信息、实测供电/通道/位速率、目标 ID/反馈 ID/模式、
原始 TX/RX 与时间、发送完成或错误、接收/丢弃计数，以及是否实际使能/旋转/停下。
不要求把每次调试写成当前指南的流水账。长日志放项目忽略的日志目录，skill 只保留
可复用结论和来源路径。
